Lesson 0006 · Phase 2: The Bitbucket daily loop · 14 min

The daily loop: branch, commit, push, open a PR to staging

You will be able to: carry a ticket from staging to an open pull request with no detours.

This is the loop you will run hundreds of times. Branch from fresh staging, commit in small meaningful steps, push, open a PR.

git switch staging
git pull --ff-only                       # start from the latest
git switch -c feature/PROJ-1234-parse-fix
# ... edit ...
git add -p                               # choose what goes in
git commit -m "PROJ-1234: handle empty input in parser"
git push -u origin HEAD                  # first push sets tracking
# Bitbucket prints a link -> Create pull request: source=your branch, target=staging

Good PR hygiene

  • Branch name: feature/PROJ-1234-short-words or bugfix/.... The Jira key links branch, PR and ticket.
  • Commits: one logical change each, message starts with the key.
  • Before pushing: git diff origin/staging...HEAD --stat shows exactly what the PR contains.
  • PR description: what, why, how tested, anything risky. Add reviewers.
  • Draft/WIP: push early; mark it draft if your Bitbucket supports it so nobody merges it.
Bitbucket: The target branch defaults to the repo's main branch; check it says staging before creating. After the first push the terminal prints a PR-creation URL.
