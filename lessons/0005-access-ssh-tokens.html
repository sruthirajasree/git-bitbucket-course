Lesson 0005 · Phase 2: The Bitbucket daily loop · 12 min

Access: SSH keys, tokens, Data Center vs Cloud

You will be able to: diagnose 'permission denied' in under a minute and know which Bitbucket you are talking to.

Authentication is separate from Git. The server must recognise you by an SSH key or an access token. Your repo's URL tells you which Bitbucket you use:

ClueProductNotes
ssh://git@bitbucket.example.com:7999/PROJECT/repo.gitData Center (self-hosted)Port 7999 is the Data Center default for SSH. Project key + repo slug in URL.
git@bitbucket.org:workspace/repo.gitCloudWorkspace + repo slug.
https://.../scm/PROJECT/repo.gitData Center over HTTPSNeeds a personal access token, not your password.

SSH setup, once per machine

ssh-keygen -t ed25519 -C "you@company.com"
cat ~/.ssh/id_ed25519.pub        # paste into Bitbucket: Profile -> SSH keys
ssh -T -p 7999 git@bitbucket.example.com   # test connection (Data Center)

Symptom to cause

ErrorUsual causeFix
Permission denied (publickey)Key not added, wrong key offered, or ssh-agent not loadedAdd the public key; ssh-add -l; ssh -vT ...
Authentication failed (https)Password used instead of token, or token expiredCreate a new HTTP access token
Repository not foundNo permission, or URL typoAsk the repo admin for read/write on the repo
Host key verification failedServer key changed or first-time prompt rejectedVerify with admin, then update ~/.ssh/known_hosts
Commits show someone else's nameuser.name/email wronggit config --global user.email ...
Bitbucket: Data Center: Profile picture -> Manage account -> SSH keys / Personal access tokens. Cloud: Personal settings -> SSH keys / App passwords or repository access tokens. Passwords are not accepted for Git over HTTPS on Cloud.
Never paste a token or private key (id_ed25519 without .pub) into chat, tickets or commits.
