Lesson 0025 · Phase 5: Hard cases · 10 min

Tags, releases and lightweight hygiene

You will be able to: tag a release, fix a bad tag, and set the configs that prevent common errors.
git tag -a v26.2.1 -m "Release 26.2.1" <sha>   # annotated (preferred)
git push origin v26.2.1                          # tags are NOT pushed by default
git tag --list 'v26*'
git show v26.2.1
# fix a wrong tag (before anyone uses it):
git tag -d v26.2.1
git push origin :refs/tags/v26.2.1
Annotated tags store author, date and message; lightweight ones are just labels. Use annotated for releases. Never move a tag others have already used: create a new version instead.

Config that prevents errors

git config --global pull.rebase true         # no 'divergent branches' nag (or false for merge)
git config --global fetch.prune true         # auto-clean dead remote branches
git config --global push.autoSetupRemote true  # first push 'just works' (git 2.37+)
git config --global rerere.enabled true      # remember conflict resolutions
git config --global merge.conflictstyle zdiff3
git config --global init.defaultBranch main
git config --global core.autocrlf input      # Linux/macOS (true on Windows)

.gitattributes for line endings

* text=auto

Aliases worth having

git config --global alias.lg "log --oneline --graph --decorate --all -20"
git config --global alias.st "status -sb"
