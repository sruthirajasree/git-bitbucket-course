Lesson 0018 · Phase 4: Undo and recover · 14 min

Tidy history: squash, reword, fixup

You will be able to: turn 'wip, fix, fix again' into clean commits before review, on your own unpushed branch.

Reviewers read your commits. Clean them before opening the PR (or before review starts).

git rebase -i origin/staging       # interactive: edit the todo list
pick  a1b2c3 PROJ-50: parse input
squash d4e5f6 wip                 # fold into previous, edit message
fixup  7a8b9c fix typo            # fold into previous, discard message
reword 1f2e3d PROJ-50: validat  # keep content, edit message
drop   9z8y7x debug print         # remove commit
edit   5c4b3a ...                 # stop here to amend/split

Fast alternative: collapse everything into one commit

git reset --soft origin/staging
git commit -m "PROJ-50: add work log"

Fixup workflow (neat habit)

git commit --fixup <sha-of-target>
git rebase -i --autosquash origin/staging
Interactive rebase rewrites ids. Only on unpushed work or your own un-reviewed branch; push afterwards with --force-with-lease. Made a mess? git rebase --abort, or git reflog.
Bitbucket: If your repo allows the Squash merge strategy, you can skip local squashing: Bitbucket squashes at merge. Check your team's convention.

Do it for real

Lab (real git, safe sandbox): squash-wip

Squash 5 'wip' commits into one clean commit.

./labs/lab.sh start squash-wip
cd ~/git-sandbox/work     # fix it here
./labs/lab.sh check squash-wip

Stuck? ./labs/lab.sh hint squash-wip. The sandbox is a local bare repo that plays Bitbucket, so nothing real is touched. Run from the course folder (~/git-bitbucket-teach) on the machine where Git is installed.
