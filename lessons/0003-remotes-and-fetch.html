Remotes, origin/* and fetch vs pull

You will be able to: explain ahead/behind, and choose fetch or pull on purpose.

origin is just the nickname for your Bitbucket URL. origin/staging on your machine is a bookmark: where staging was the last time you talked to Bitbucket. It does not update by itself.

CommandChanges your branch?Use when
git fetchNo: only updates origin/* bookmarksYou want to look first (safe any time)
git pullYes: fetch + merge (or rebase)You want to update the branch you are on
git pull --ff-onlyOnly if no merge is neededUpdating staging: fails loudly instead of making a merge
git pushUpdates Bitbucket, not your filesPublishing your commits
Habit: git fetch --prune then git status -sb. You see ahead N, behind M before touching anything. Set git config --global fetch.prune true so deleted remote branches disappear from your list.
