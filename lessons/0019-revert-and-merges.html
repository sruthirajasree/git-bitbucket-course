Lesson 0019 · Phase 4: Undo and recover · 12 min

Reverting pushed work, including merges

You will be able to: undo a bad commit or a whole merged PR on shared staging without rewriting history.

On shared branches history is append-only. git revert creates a new commit that applies the opposite diff.

git revert <sha>                # one commit
git revert A^..B                # a range (oldest^..newest)
git revert -n <sha>             # stage the undo without committing (to combine)
git push

Reverting a merge commit

A merge has two parents. Tell Git which line to keep:

git revert -m 1 <merge-sha>     # -m 1 = keep parent 1 (the mainline, e.g. staging)
The re-merge trap: after reverting a merge, merging the same branch again brings nothing (Git thinks it is already merged). To re-introduce it: first git revert <the-revert-commit>, or rebase/recreate the branch, then merge.

Do it for real

Lab (real git, safe sandbox): revert-pushed

A bad commit is on shared staging with a good one after it. Revert only the bad one and push.

./labs/lab.sh start revert-pushed
cd ~/git-sandbox/work     # fix it here
./labs/lab.sh check revert-pushed

Stuck? ./labs/lab.sh hint revert-pushed. The sandbox is a local bare repo that plays Bitbucket, so nothing real is touched. Run from the course folder (~/git-bitbucket-teach) on the machine where Git is installed.
