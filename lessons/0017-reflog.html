Lesson 0017 · Phase 4: Undo and recover · 12 min

The safety net: reflog

You will be able to: recover commits after a bad reset, rebase, or deleted branch.

The reflog is your local flight recorder: every position HEAD has been, newest first. Commits are rarely deleted, only unreferenced.

$ git reflog
3f2a1b HEAD@{0}: reset: moving to origin/staging
a9b8c7 HEAD@{1}: commit: PROJ-77 step 3     <- your lost work
5d4e3f HEAD@{2}: commit: PROJ-77 step 2
...
Lost it how?Recover
reset --hardgit reflog then git reset --hard HEAD@{1}
Bad rebase / mergegit reset --hard ORIG_HEAD
Deleted branchgit branch name <sha-from-reflog>
Dropped stashgit fsck --no-reflog | grep dangling then git stash apply <sha>
Uncommitted editsNot recoverable. Check editor local history/backups
Limits: reflog is local only (not shared, not on Bitbucket), entries expire (default ~90 days reachable / 30 unreachable), and it never tracks uncommitted work. Commit often.
Before any risky command: git branch backup/$(date +%F). A label is a free insurance policy.

Do it for real

Lab (real git, safe sandbox): lost-commits

A hard reset removed 3 commits. Recover them using the reflog.

./labs/lab.sh start lost-commits
cd ~/git-sandbox/work     # fix it here
./labs/lab.sh check lost-commits

Stuck? ./labs/lab.sh hint lost-commits. The sandbox is a local bare repo that plays Bitbucket, so nothing real is touched. Run from the course folder (~/git-bitbucket-teach) on the machine where Git is installed.
