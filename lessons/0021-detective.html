Lesson 0021 · Phase 4: Undo and recover · 12 min

Git detective: blame, log -S, bisect

You will be able to: find who changed a line, when a string appeared, and which commit broke the build.
QuestionCommand
Who last touched these lines?git blame -L 10,30 file.py
When did this string appear/disappear?git log -S"timeout_ms" --oneline
History of a file, even across renames?git log -p --follow -- path/file
What changed between two refs?git diff origin/staging...HEAD --stat
Which commit broke it?git bisect (below)
Which branches contain this commit?git branch -a --contains <sha>
Is X already in staging?git merge-base --is-ancestor X origin/staging && echo yes

Bisect: binary search for the bad commit

git bisect start
git bisect bad                 # current commit is broken
git bisect good v26.1.0        # known-good tag or sha
# Git checks out the midpoint: build/test, then:
git bisect good    # or: git bisect bad     (repeat ~log2(N) times)
git bisect reset               # return to your branch
# automate:  git bisect run ./test.sh
Bisect works best with small commits and a script that exits 0 (good) / non-zero (bad). It is another reason for one logical change per commit.
