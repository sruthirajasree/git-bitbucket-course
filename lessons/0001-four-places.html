The four places your code lives

You will be able to: say which place any command moves changes between, and why uncommitted work cannot be recovered.

Every Git command moves changes between four places. Learn these once and the rest of the course is just variations.

Working tree --git add--> Index (staging) --git commit--> Local repo --git push--> Remote (Bitbucket)
   (your files)  <--restore--                  <--reset--                  <--fetch/pull--    origin/*
PlaceWhat it isHow to see it
Working treeThe files you editgit status, git diff
Index (staging area)What the next commit will containgit diff --staged
Local repoCommits and branches in .gitgit log
RemoteBitbucket's copy; you hold bookmarks origin/*git fetch then git log origin/staging

A pull request is not a Git thing

A PR is a Bitbucket record that says "please merge branch X into staging", with reviews, approvals and build results. Git itself does not know it exists. Pushing more commits to X updates it.

Two rules that answer 80% of what to do: (1) Uncommitted edits exist only in the working tree: Git cannot bring them back. (2) Unpushed history is yours to rewrite; pushed and shared history is append-only (use revert).
