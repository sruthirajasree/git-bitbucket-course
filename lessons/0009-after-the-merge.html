Lesson 0009 · Phase 2: The Bitbucket daily loop · 10 min

After the merge: sync staging and clean up

You will be able to: clean local and remote branches safely, and explain why git branch -d sometimes refuses.

The PR merged. Now return to a clean state so you never build on stale code.

git switch staging
git pull --ff-only
git fetch --prune                     # forget deleted remote branches
git branch -d feature/PROJ-1234-x   # safe delete
# if squash merged, Git cannot tell it is merged:
git branch -D feature/PROJ-1234-x   # after confirming the PR says MERGED
git push origin --delete feature/PROJ-1234-x   # if Bitbucket didn't auto-delete

Why -d refuses after a squash

Before -D, confirm the PR shows Merged and the squash commit is on origin/staging: git log origin/staging --oneline --grep PROJ-1234.
Bitbucket: Tick 'Delete source branch' when merging, or ask admins to enable it by default.
