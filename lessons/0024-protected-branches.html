Lesson 0024 · Phase 5: Hard cases · 12 min

Permissions, protected branches and hooks

You will be able to: decode a server rejection message and know whom to ask.

Some failures are not Git problems: they are server rules. Bitbucket can restrict who may push, require PRs, forbid history rewrites, run hooks and check merge conditions.

MessageMeaningWhat to do
remote: pre-receive hook declined / refusing to update protected branchBranch permissions or a hook rejected your pushRead the lines above it. Move commits to a feature branch and open a PR
You are not permitted to push to this branchBranch permissionOpen a PR; ask admin if you need access
force push denied / rewriting history is not allowedRewrites blocked on that branchUse revert; never force on staging
file exceeds size limitSize hookRemove or use LFS (lesson 22)
commit message does not match ... / Jira issue requiredCommit-message or Jira hookAmend message to include PROJ-NNNN
PR merge button greyed outMerge checks (approvals, builds, tasks)Read the checks panel (lesson 7)

Fixing a rejected push to a protected branch

Bitbucket: Data Center: Repository settings -> Branch permissions / Hooks / Merge checks. Cloud: Repository settings -> Branch restrictions / Merge checks. If you cannot see these pages you are not an admin: ask one. Never try to bypass a protection.
