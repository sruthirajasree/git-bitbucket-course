Merge conflicts, read and resolve

You will be able to: read conflict markers, choose the right content, and finish or abort calmly.

A conflict is not an error: Git is saying "both sides changed the same lines, you decide". Git stops, marks the file and waits.

<<<<<<< HEAD
TIMEOUT = 45          <- YOUR side (the branch you're on)
=======
TIMEOUT = 60          <- THEIR side (what you're merging in)
>>>>>>> origin/staging

The 5-step routine

1. git status                      # 'Unmerged paths' lists conflicted files
2. open the file; decide the final content (may be neither side, or both)
3. delete the <<<<<<< ======= >>>>>>> lines
4. git add <file>                  # tells Git 'resolved'
5. git commit                      # finishes a merge (git rebase --continue for rebase)
Escape hatch: git merge --abort    # back to before you started

Decision guide

SituationDo
Both changes are neededCombine them by hand; run tests
Only yours is rightgit checkout --ours file (merge) then git add
Only theirs is rightgit checkout --theirs file then git add
You do not understand their changeAsk the author. git log -p origin/staging -- file shows why it changed
Messy, want to retrygit merge --abort and start over
Generated/lock file conflictRe-generate it (e.g. rerun the build tool), do not hand-edit
Both deleted/modified (DU/UD)Decide: keep file (git add file) or delete (git rm file)
Do not commit with markers left in. Search before committing: git diff --check and grep -rn '<<<<<<<' .
Config that helps: git config --global merge.conflictstyle zdiff3 shows the original text between the markers.

4 questions. Pick an answer from memory; you get instant feedback and an explanation. Finish with 3 of 4 to tick this lesson off.
