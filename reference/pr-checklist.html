PR checklist

Before you click Create pull request, and before you click Merge.

Before opening

  • Branch starts from fresh staging; name has the Jira key.
  • git diff origin/staging...HEAD --stat shows only intended files.
  • Commits are small, messages start with PROJ-N.
  • No secrets, large files, build output or debug prints.
  • Tests/build pass locally.
  • Target branch is staging.
  • Description: what, why, how tested, risk.

During review

  • Respond to every comment; resolve tasks.
  • Push new commits, do not rewrite history under review.
  • Update from staging by merge if comments exist.
  • Re-request review after fixes.

Before merging

  • Required approvals and builds green; no open tasks.
  • Branch is current with staging and conflict-free.
  • Merge strategy matches team convention.
  • Tick delete-source-branch if offered.

After merging

  • git switch staging && git pull --ff-only && git fetch --prune
  • Delete local branch (-D after squash).
  • Move the Jira ticket.
